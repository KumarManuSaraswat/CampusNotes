## Cloudinary 401 diagnosis

The verified application defects were the direct redirect to a signed delivery URL and the client treating any response body as a file. Cloudinary documents `private_download_url` as the time-limited signed access method for private and authenticated originals, and the server now uses that SDK method. See [Cloudinary's upload API reference](https://cloudinary.com/documentation/image_upload_api_reference) and [media access control guide](https://cloudinary.com/documentation/control_access_to_media).

The specific account-level cause of the reported `401 deny or ACL failure` could not be confirmed from this repository: there are no live Cloudinary credentials, asset identifiers from the failing account, or provider response headers/logs available here. The change addresses the access method and prevents a provider error from being presented as a PDF; a live Cloudinary upload/preview/download still needs verification with the deployment's credentials and an existing authenticated asset. No mocked test is presented as proof of live Cloudinary access.

## Other non-AI flows reviewed

- Note upload checks file signatures, accepted MIME types, extensions, and configured size limits before storage; failed database creation attempts remove the uploaded object. The upload page disables its submit button while a request is active.
- Note listing and detail remain public, matching the current public discovery product behavior. Mutations continue to use authentication and ownership/moderator checks.
- The persisted API journey test exercises registration/login/logout, protected mutation, note upload/edit/delete rules, keyword/metadata filters, sorting/pagination, vote switching/removal/self-vote prevention, reputation reversals, request duplicate/fulfillment rules, report duplicate handling, moderator authorization/review, and profile data. MongoDB transactions require a replica set, which the integration test provisions locally.
- The AI processing route remains disabled unless explicitly configured. This audit adds no AI processing, recommendations, or generated metadata behavior.
- API request validation, rate limits, origin checks for mutations, HttpOnly session cookies, and ownership enforcement remain in place.

## Verification

`npm run typecheck`, `npm run lint`, `npm test`, and `npm run build` all passed. The API integration suite additionally checks malformed/empty/oversize upload rejection (including a PDF missing its end marker), PDF/JPEG/PNG byte delivery, filenames with spaces and punctuation, both disposition modes, and Cloudinary failure mapping. PDF validation checks its header and end marker; it is not a full PDF parser. Server API tests mock the Cloudinary adapter and verify application response handling; they do not verify external Cloudinary credentials, asset ACL configuration, or network access. No automated browser runner is configured in this repository.

## Deployment and remaining steps

- Deployment readiness: code and builds are ready for staging verification, but live file delivery is not certified until staging has the correct `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, and `CLOUDINARY_API_SECRET` and an authenticated test asset is previewed and downloaded.
- Manual dashboard change: none is proven necessary from available evidence. If `private_download_url` still returns 401 with deployment credentials, inspect the exact asset's delivery type/resource type and Cloudinary product-environment ACL/security settings; do not make assets public as a workaround.
- Existing assets: records with `storageProvider`, `storagePublicId`, `storageResourceType`, and `fileType` can use this server-side route without re-upload. No schema migration is required. Records missing an identifier return a safe unavailable-file response.
- AI integration: no AI processing was added or altered. Existing processing fields and the disabled endpoint behavior remain intact.
- Known unresolved issue: the reported Cloudinary account-level 401 cause and live delivery cannot be verified without the affected Cloudinary environment and credentials.
